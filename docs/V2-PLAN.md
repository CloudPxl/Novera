# V2: fine-tuning

V1 closed on 2026-10-13 (`docs/audits/2026-10-13-v1-final-audit.md`). The product works end to
end, and every guarantee in CLAUDE.md has a test or a verifier behind it. V2 does not add
capability. It makes Novera findable, fast and polished, and it waits deliberately for the
steps that need a real company.

## Waiting on the legal entity (PFA or SRL)

None of these can be done honestly before the entity exists. The code already refuses to
proceed without them.

| Item | What it needs | Where the code waits |
|---|---|---|
| Company details on the site and on invoices | Name, registration number, registered office, and for an SRL the share capital (Law 31/1990 art. 74) | `data/legal/entity.ts`, all `null`; live checkout refuses until complete |
| Legal texts in force | Counsel review of Terms 0.2, Privacy, DPA, Refunds, AUP and AI Testing Scope; questions 36–42 | `/legal/*` stay `noindex` with the draft banner until approved and archived (`data/legal/archive.ts`) |
| Privacy notice linked from sign-up, support and apply | An approved privacy notice | Readiness L3 |
| VAT and reverse charge, VAT display, Stripe Tax | The accountant's answer (question 42) | Stripe Tax off |
| Live Stripe | A Stripe account for the entity, live prices, then `BILLING_ALLOW_LIVE` | `billingConfig` refuses live keys without approval |
| Published prices | Billing open | The home page names plans, not prices |
| Organization structured data (schema.org) | The entity's name and address | Not added: it would state facts that do not exist yet |

## Track 1: technical SEO (first)

Measured 2026-10-13:
- `robots.ts` and `sitemap.ts` exist and are correct about what is private.
- The home page has a title and a description.
- Documentation pages have a title, a description and a canonical.

The gaps:

1. **`metadataBase`** in `src/app/layout.tsx` (`https://www.nover.space`). Production's canonicals are relative today (`<link rel="canonical" href="/docs/api"/>`), and every Open Graph URL depends on this.
2. **A title template** (`%s · Novera`), plus a description on every public page: `/docs`, `/guide`, `/support`, `/apply`, `/status` and `/sign-in`. A canonical on each.
3. **Open Graph and Twitter cards** for the home page, documentation and guide, with images generated by `opengraph-image.tsx` (`next/og`). Under the language rule: no "compliant" and no "certified".
4. **Sitemap `lastModified`** from each documentation file's last change, so crawlers re-read only what moved.
5. **`SoftwareApplication` JSON-LD** on the home page: name, category and description only. No price until prices are published, and no Organization until the entity exists.
6. **Housekeeping:** remove Next's starter files from `public/` (`file.svg`, `globe.svg`, `next.svg`, `vercel.svg`, `window.svg`; none is referenced); add a web manifest and an Apple touch icon; check the 404 and error pages for `noindex`.
7. **A test** that every sitemap URL answers 200 and is indexable, every public page has a unique title and description, and no app or report path is in the sitemap.

## Track 2: speed

1. **Every route renders on demand** (`ƒ` in the build), the public pages included. The nonce Content-Security-Policy in `proxy.ts` requires it. Measure first: Lighthouse on mobile for `/`, `/docs` and one documentation page. Then decide whether the public, non-interactive pages can be cached, with a hash-based policy for their inline scripts, without weakening the CSP on the app.
2. **JavaScript on the public pages:** what the home page's evidence preview costs, and whether it can load after the first paint.
3. **Fonts:** Geist and JetBrains Mono. Check `display` and preload, and that only the subsets used are loaded.

## Track 3: content for search

1. **A keyword map** for what buyers search: AI support agent testing, EU AI Act evidence for chatbots, GDPR testing for customer-service AI, and regression testing for LLM agents. Each phrase is matched to an existing page before any new page is written.
2. **Documentation pages as landing pages.** They are already public and canonical: sharpen each first paragraph and add internal links between them.
3. **Comparison pages** (Promptfoo, DeepEval, LangSmith and others), only from `docs/COMPETITION.md` rows with a fetched source and a date. Each says what they do better.
4. **The sample report** as an indexable page, labelled test data, with its notice.

Every customer-facing sentence passes the language rule (`src/lib/report/language.ts`) and the legal tests. Search copy is where compliance-guarantee wording creeps in first.

## Track 4: polish found by the V1 audit

1. `/billing` keeps `next=` through sign-in; `/dashboard` and the other app pages do not. Return a signed-out person to the page they asked for, through the same allow-list (`src/lib/auth/redirects.ts`).
2. A **read-only production smoke** script (`verify:prod`) built from the audit's `curl` checks, so the release check is one command.
3. **The local stack:** clear the leftover test schedule that blocks `verify:schedules`, and decide whether local GoTrue should require email confirmation as production does, so the sign-up walk covers the emailed link there too.

## How V2 is verified

As V1 was, with search added:

- axe and overflow at 390, 1024 and 1440 on every page touched;
- before and after Lighthouse scores per public page, kept with the commit;
- Search Console's coverage report once verification is in place.
