## The isolated test environment

All destructive and concurrent tests ran against a local stack, never against production.

| Part | How |
|---|---|
| Database | Local Supabase 2.118.0 in Docker, Postgres 17.6, recreated empty (`supabase stop --no-backup && supabase start`) |
| Schema | `npm run migrate` from zero: all 44 migrations applied, exit 0 |
| Seeds | `npm run seed:suites`, `npm run seed:docs` (14 pages) |
| App | A `git archive` copy of `b18dec7`, served by `next dev -p 3100` |
| App environment | Local Supabase URL and keys; a freshly generated `NOVERA_ENCRYPTION_KEY` (`openssl rand -base64 32`). No model provider, Resend, Vercel or GitHub credentials |
| Agents | The repo's own fixture (`/api/test-agent`), plus a new local responder (`harness/responder.mts`) for delayed success, delayed 502, malformed JSON, redirect, connection hang, stalled body, oversized body and wrong response path |
| Webhook receivers | Local HTTP servers inside each harness script |
| Cron | pg_cron absent at first (to reproduce R1); enabled afterwards and scheduled with the migrations' own statements |
| Browser | Headless Chrome via Playwright, never the user's session |

**Deviations from production, and why:**

1. **SSL to the database.** Four scripts force TLS with `rejectUnauthorized: false`; local Postgres has
   no TLS. A preload (`harness/local-pg.mjs`) drops TLS for `127.0.0.1` only. No repository file was
   edited.
2. **Setup the verifiers do not do themselves.** `verify:access` and `verify:mcp` need a sealed report,
   and `verify:retention` needs pg_cron. Both were reproduced as failures from an empty database first,
   then supplied (`harness/seed-report.mts`, `harness/cron-setup.sql`).
3. **Local `next dev` is not Vercel.** There is no 60-second kill and no Fluid compute, and the response
   headers differ.
